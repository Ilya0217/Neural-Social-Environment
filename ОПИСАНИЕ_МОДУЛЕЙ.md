# Описание модулей программного интерфейса

## Проектирование программного интерфейса для взаимодействия с языковыми моделями

В рамках проекта разработан многоуровневый программный интерфейс, обеспечивающий структурированное взаимодействие между агентами, управляемыми моделями DeepSeek и ChatGPT, и модулем orchestration, отвечающим за организацию диалога. В отличие от традиционного пользовательского интерфейса, данный инструмент предназначен для автоматического управления ролевыми конфигурациями, стилевыми параметрами и контекстными слоями, которые определяют стратегию поведения виртуальных участников.

Архитектура интерфейса построена по модульному принципу, позволяющему гибко подключать новые роли, генеративные модели, сценарии и аналитические инструменты. Каждый компонент отвечает за конкретную область функциональности: управление агентами, настройку генерации, маршрутизацию сообщений, контекстное сопровождение, анализ диалогов и визуализацию социальной динамики. Такой подход обеспечивает масштабируемость системы и возможность расширения функционала в зависимости от задач исследования.

## Основные компоненты интерфейса и их функции

### 1. Модуль управления конфигурацией (config.py)

Модуль централизованного управления параметрами системы и настройками взаимодействия с языковыми моделями. Обеспечивает:

- **Управление параметрами генерации**: настройка температуры (temperature), максимального количества токенов (max_tokens), выбор модели (MODEL) через переменные окружения
- **Конфигурация агентов**: определение базовых ролей (explorer, critic, facilitator) с их цветовыми схемами для визуализации
- **Управление фазами диалога**: конфигурация последовательности фаз (ideation, prioritization, planning) с длительностью и инструкциями для каждой фазы
- **Система настроения агентов**: параметры динамического изменения настроения (MOOD_DECAY, MOOD_DELTA) и корректирующие инструкции (MOOD_GUIDANCE)
- **Настройка визуализации**: параметры окна для анализа взаимодействий (VIZ_EDGE_WINDOW), количество подписываемых рёбер графа

### 2. Модуль определения агентов (agents.py)

Абстракция для представления виртуальных участников диалога. Реализует:

- **Dataclass Agent**: структура данных, содержащая имя агента, роль (nature), цвет для визуализации, флаг человеческого участия
- **Динамическая генерация системных промптов**: свойство `system_prompt`, которое формирует промпт на основе роли и персональных характеристик через вызов `build_system_prompt()`
- **Поддержка персонализации**: поле `persona` для хранения индивидуальных характеристик агента, собранных через опросник

### 3. Модуль базовых промптов (prompts.py)

Формирование системных инструкций для языковых моделей. Включает:

- **Базовые промпты ролей (BASE_SYSTEM_PROMPTS)**: предопределённые промпты для ролей explorer, critic, facilitator с описанием личности, стиля общения и поведенческих паттернов
- **Функция сборки промптов (build_system_prompt)**: объединение базового промпта роли с персонализированными данными из опросника, генерация динамических промптов для кастомных ролей
- **Общие инструкции сессии**: 
  - `SESSION_GOAL` — установка контекста реального разговора между реальными людьми
  - `HUMAN_STYLE` — инструкции по естественному стилю общения с использованием неформального обращения
  - `STRUCTURE_INSTRUCTION` — требования к структурированному формату ответа (JSON с полями reply, tone, emotion, target)
- **Контексты окружений (ENV_CONTEXTS)**: предопределённые сценарии (университет, стартап, исследовательский семинар)

### 4. Модуль продвинутых промптов (advanced_prompts.py)

Реализация техник инженерии промптов для повышения качества ответов. Содержит:

- **Chain-of-Thought шаблон (COT_TEMPLATE)**: структурированный процесс рассуждения перед ответом (анализ контекста, определение перспективы роли, выбор адресата, формулировка вклада)
- **Продвинутые промпты ролей (ADVANCED_SYSTEM_PROMPTS)**: расширенные версии промптов для ролей explorer, critic, facilitator, analyst, innovator с встроенными CoT-инструкциями
- **Контекстно-зависимые руководства (CONTEXT_GUIDELINES)**: адаптация промптов в зависимости от фазы диалога (early_discussion, mid_discussion, late_discussion, conflict_detected, stuck_discussion)
- **Few-shot примеры (FEW_SHOT_EXAMPLES)**: примеры хороших и плохих ответов для обучения модели
- **Функция генерации продвинутых промптов (get_advanced_prompt)**: сборка промпта с опциональным включением CoT, контекстных руководств и примеров
- **Детекция типа контекста (detect_context_type)**: автоматическое определение текущего состояния диалога на основе истории сообщений

### 5. Модуль инициализации профилей (profiles.py)

Сбор и форматирование персональных характеристик агентов. Обеспечивает:

- **Опросник агентов (QUESTION_BANK)**: набор вопросов для сбора информации о бэкграунде, мотивации, речевых привычках, любимых темах, реакции на стресс, характерных фразах
- **Дефолтные ответы (DEFAULT_ANSWERS)**: предустановленные характеристики для стандартных ролей
- **Форматирование персоны (_format_persona)**: преобразование ответов опросника в структурированный текст для включения в системный промпт
- **Инициализация агентов (initialize_agents)**: создание списка агентов с персонализированными промптами, поддержка интерактивного режима и сохранения профилей в JSON
- **Инициализация из конфигурации (initialize_agents_from_config)**: создание агентов из веб-интерфейса с передачей данных опросника

### 6. Модуль управления диалогом (dialogue_manager.py)

Центральный оркестратор многоагентного взаимодействия. Реализует:

- **Класс DialogueManager**: управление состоянием диалога, историей сообщений, текущим ходом, окном взаимодействий для визуализации
- **Управление фазами диалога**: 
  - `current_phase()` — определение текущей фазы на основе номера хода
  - `_phase_block()` — генерация инструкций для текущей фазы
- **Система настроения агентов**:
  - `agent_moods` — словарь текущих настроений агентов
  - `_decay_moods()` — постепенное затухание настроения
  - `_adjust_mood()` — изменение настроения на основе тона сообщения
  - `_mood_guidance()` — генерация корректирующих инструкций при экстремальных значениях настроения
- **Выбор следующего говорящего (next_speaker_idx)**: round-robin алгоритм с приоритетом ответа адресату предыдущего сообщения
- **Сборка сообщений для модели (build_messages)**: формирование полного системного промпта, включающего:
  - Базовый промпт роли с персоной
  - Цель сессии (SESSION_GOAL)
  - Инструкции текущей фазы
  - Специфичные инструкции для университетского контекста
  - Корректировка настроения
  - История последних сообщений
  - Рекомендации по выбору адресата
  - Стиль общения (HUMAN_STYLE)
  - Инструкции по структуре ответа
- **Генерация ответа модели (model_turn)**: 
  - Использование function calling API для структурированного ответа
  - Fallback на JSON mode при отсутствии function calling
  - Многоуровневая обработка ошибок парсинга с попытками извлечения JSON из текста
  - Валидация и исправление адресата при несоответствии списку допустимых
- **Шаг симуляции (step)**: 
  - Выбор говорящего
  - Получение ответа (через модель или человеческий ввод)
  - Валидация сообщения через ValidationPipeline
  - Обновление истории и настроений
  - Возврат записи хода и графа взаимодействия

### 7. Модуль валидации (validators.py)

Многоуровневая система проверки качества и этичности сообщений. Состоит из:

- **Базовый валидатор (BaseValidator)**: абстрактный класс для всех типов валидаторов
- **Грамматический валидатор (GrammaticalValidator)**: проверка длины сообщения, пунктуации, капитализации, повторяющихся знаков препинания, использования заглавных букв
- **Валидатор языка (LanguageValidator)**: обеспечение использования только английского языка (детекция кириллицы)
- **Валидатор логической согласованности (LogicalConsistencyValidator)**: проверка корректности адресата (не адресация самому себе, адресат в списке участников), разнообразия адресатов, релевантности контексту
- **Валидатор соответствия тона и эмоции (ToneEmotionValidator)**: проверка согласованности между тоном (positive/neutral/negative) и эмоцией
- **Валидатор токсичности (ToxicityValidator)**: детекция оскорбительного, вредного или токсичного контента
- **Валидатор уважительности (RespectValidator)**: проверка на неуважительные фразы и конструктивность общения
- **Валидатор профессиональных границ (ProfessionalBoundariesValidator)**: обеспечение соблюдения профессионального контекста
- **Валидатор моральных схем (MoralSchemaValidator)**: проверка на нарушение принципов справедливости, инклюзивности, предотвращения вреда
- **Пайплайн валидации (ValidationPipeline)**: оркестрация всех валидаторов, агрегация результатов, определение блокирующих ошибок, форматирование отчётов

### 8. Модуль аналитики (analytics.py)

Расчёт метрик качества диалога и генерация гипотез. Включает:

- **Вычисление метрик (compute_metrics)**: 
  - Средний тон диалога (avg_tone) на основе трёхзначной шкалы (-1, 0, +1)
  - Процент адресации (targeting_rate)
  - Энтропия эмоций (emotion_entropy) по формуле Шеннона
  - Средняя длина ответов (avg_reply_words)
  - Взаимность (reciprocity) — доля взаимных обменов сообщениями
  - Задержка ответа (avg_addressing_delay) — среднее количество ходов до ответа адресату
  - Процент вопросов (question_rate)
  - Процент упоминаний имён (reference_rate)
  - Процент действий (actionability_rate) — упоминание ключевых слов действий
  - Распределение разговорной активности (talk_share) по агентам
  - Степени входа и выхода (in_degree, out_degree) для графа взаимодействий
- **Генерация гипотез (hypotheses_from_metrics)**: эвристические правила для выявления проблем (доминирование агента, негативный тон, низкая адресация, высокая задержка) и интеграция научных гипотез из scientific_analytics
- **Рендеринг отчёта (render_markdown_report)**: форматирование метрик в Markdown с таблицами, эмодзи-индикаторами, разбивкой по окнам и общим показателям

### 9. Модуль научной аналитики (scientific_analytics.py)

Применение современных научных фреймворков для анализа социальных взаимодействий. Реализует:

- **Анализ социальных сетей**: расчёт плотности сети, коэффициента кластеризации, центральности агентов (in/out), промежуточности (betweenness)
- **Модель группового развития (Wheelan, 2009)**: определение стадии развития группы (forming, storming, norming, performing) на основе метрик взаимодействия
- **Реляционная координация (Gittell, 2002)**: измерение групповой сплочённости
- **Таксономия диалоговых актов (ISO 24617-2)**: классификация сообщений на task-oriented и socio-emotional, расчёт соотношения положительных и отрицательных актов
- **Размерностная модель эмоций (Russell & Barrett, 1999)**: определение доминирующей эмоции и распределения эмоционального климата
- **Анализ чередования реплик (CMDA, Herring, 2004)**: расчёт неравенства в распределении ходов (коэффициент Джини), процент завершённых смежных пар
- **Генерация научных гипотез (generate_scientific_hypotheses)**: формулировка выводов на основе научных фреймворков с указанием источников

### 10. Модуль визуализации (visualize.py)

Построение графов взаимодействий между агентами. Обеспечивает:

- **Функция draw_interactions_prog**: создание графа с использованием NetworkX и Matplotlib
- **Визуализация рёбер**: отображение направленных связей между агентами с цветовой кодировкой тона (зелёный — positive, жёлтый — neutral, красный — negative)
- **Окно анализа**: визуализация только последних N взаимодействий для актуальности
- **Позиционирование узлов**: использование spring layout для оптимального расположения агентов
- **Подписи рёбер**: отображение текста сообщений на наиболее активных связях

### 11. Модуль веб-интерфейса (web_app.py)

Flask-приложение для интерактивного управления симуляцией. Реализует:

- **Состояние приложения (AppState)**: хранение текущего DialogueManager, логгера, метрик, гипотез, научных отчётов
- **Маршрут главной страницы (/)**: отображение интерфейса выбора окружения и управления симуляцией
- **API старта сессии (/api/start)**: инициализация нового диалога, очистка предыдущих логов и графиков, настройка агентов
- **API шага симуляции (/api/step)**: генерация следующего сообщения, сохранение в лог, обновление метрик и графов при необходимости
- **API состояния (/api/state)**: получение текущего состояния диалога, последнего графа, метрик, гипотез
- **API научного анализа (/api/scientific)**: предоставление научного отчёта и гипотез
- **Сервирование файлов (/outputs/<filename>)**: отдача сгенерированных графиков и отчётов
- **Скачивание логов (/download/log, /download/log_md)**: экспорт диалога в JSONL и Markdown форматах

### 12. Модуль CLI интерфейса (main.py)

Командная строка для запуска симуляции. Включает:

- **Выбор окружения**: интерактивный выбор контекста диалога из списка доступных
- **Инициализация агентов**: сбор персональных характеристик через опросник
- **Интерактивный режим**: пошаговая генерация сообщений по нажатию Enter
- **Автоматическое логирование**: сохранение каждого хода в JSONL и Markdown форматах
- **Периодическая визуализация**: автоматическое создание графов и отчётов каждые N ходов

### 13. Модуль логирования (io_logger.py)

Сохранение истории диалога в структурированных форматах:

- **JSONL формат**: каждая строка — JSON объект с полями turn, speaker, target, reply, tone, emotion, timestamp
- **Markdown формат**: человекочитаемое представление диалога с форматированием
- **Блоки метрик**: вставка отчётов о метриках в Markdown лог

### 14. Модуль мониторинга производительности (performance_monitor.py)

Отслеживание использования API и оптимизация затрат:

- **Метрики API вызовов**: количество вызовов, использованные токены (prompt + completion), задержка ответа
- **Расчёт стоимости**: оценка затрат на основе тарифов OpenAI
- **Статистика успешности**: процент успешных запросов, количество ошибок
- **Генерация отчётов**: детальная статистика по использованию API

### 15. Модуль кэширования (cache_manager.py)

Оптимизация количества API вызовов через кэширование:

- **LRU кэш с TTL**: кэширование ответов с ограничением по времени жизни
- **Семантическое кэширование**: поиск похожих контекстов через Jaccard similarity для переиспользования ответов
- **Персистентность**: сохранение кэша на диск для переиспользования между сессиями
- **Статистика эффективности**: отслеживание hit rate и экономии API вызовов

### 16. Модуль экспорта (export_manager.py)

Экспорт результатов в различные форматы для анализа:

- **CSV экспорт**: табличное представление для статистического анализа
- **Excel экспорт**: многостраничные файлы с диалогом и метриками
- **JSON экспорт**: полная структурированная информация
- **Markdown отчёты**: исследовательские отчёты с executive summary, метриками, примерами диалогов

## Интеграция компонентов

Все модули интегрированы через единый интерфейс `DialogueManager`, который координирует работу компонентов:

1. **Инициализация**: `config.py` → `profiles.py` → `agents.py` → `DialogueManager`
2. **Генерация ответа**: `DialogueManager.build_messages()` → `prompts.py` + `advanced_prompts.py` → API модели → `DialogueManager.model_turn()`
3. **Валидация**: `DialogueManager.step()` → `validators.py` → логирование результатов
4. **Анализ**: `DialogueManager.history` → `analytics.py` + `scientific_analytics.py` → метрики и гипотезы
5. **Визуализация**: `DialogueManager.history` → `visualize.py` → граф взаимодействий
6. **Экспорт**: `DialogueManager.history` + метрики → `export_manager.py` → файлы различных форматов

Такая архитектура обеспечивает разделение ответственности, возможность независимого тестирования компонентов и гибкое расширение функциональности системы.

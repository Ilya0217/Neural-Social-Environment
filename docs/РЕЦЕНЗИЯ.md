## Тема: Симулятор диалогов мультиагентной системы с аналитикой и валидацией

## 1️⃣ Архитектура построения модели и принципы ее реализации

### Архитектура

Система построена по **модульной архитектуре** с четким разделением ответственности:

```
┌─────────────────────────────────────────────────────┐
│               AGENT DIALOGUE SIMULATOR               │
├─────────────────────────────────────────────────────┤
│                                                      │
│  ┌──────────────┐  ┌──────────────┐  ┌───────────┐ │
│  │   Agents     │  │   Dialogue   │  │ Validation│ │
│  │   Layer      │→ │   Manager    │→ │  Pipeline │ │
│  └──────────────┘  └──────────────┘  └───────────┘ │
│         ↓                 ↓                 ↓        │
│  ┌──────────────┐  ┌──────────────┐  ┌───────────┐ │
│  │  Prompts +   │  │  Analytics   │  │    I/O    │ │
│  │  LLM (GPT)   │  │  + Metrics   │  │  Logger   │ │
│  └──────────────┘  └──────────────┘  └───────────┘ │
│                           ↓                          │
│                  ┌──────────────┐                   │
│                  │ Visualization │                   │
│                  │  (NetworkX)   │                   │
│                  └──────────────┘                   │
└─────────────────────────────────────────────────────┘
```

### Основные компоненты

#### A) **Агенты** (`agents.py`)
- Каждый агент имеет: имя, характер (nature), цвет (для визуализации)
- Характер определяет стиль общения через **системные промпты**:
  - **Explorer** — любопытный, задает вопросы
  - **Critic** — замечает риски и недочеты
  - **Facilitator** — сглаживает конфликты, координирует
- Реализация: dataclass с property `system_prompt`

#### B) **Менеджер диалога** (`dialogue_manager.py`)
Центральный компонент, управляющий процессом:

1. **Выбор говорящего**: round-robin с алгоритмом разнообразия
   - Приоритет адресату из предыдущего сообщения
   - Предотвращение "пинг-понга" (если A↔B повторяется, выбирается C)
   
2. **Формирование контекста**: последние 8 сообщений + инструкции
   
3. **Вызов модели**: OpenAI GPT-4o-mini через **function calling**
   - Инструмент: `submit_agent_turn` с JSON-схемой
   - Гарантирует структурированный ответ: `{reply, tone, emotion, target}`
   
4. **Валидация**: многоуровневая проверка (см. раздел 3)
   
5. **Логирование**: JSONL + Markdown

#### C) **Аналитика** (`analytics.py`)
Вычисляет метрики каждые 5 ходов:

| Метрика | Формула | Интерпретация |
|---------|---------|---------------|
| Средняя тональность | \(\frac{1}{N}\sum \text{score}(tone_i)\), где score=+1/0/-1 | >0.2: позитивный диалог<br><-0.2: конфликт |
| Энтропия эмоций | \(H = -\sum p(e) \log_2 p(e)\) | 0-0.5: низкое разнообразие<br>>1.5: высокая эмоциональность |
| Взаимность | \(\frac{\text{пары с A→B и B→A}}{\text{всего пар}}\) | >0.7: высокая вовлеченность |
| Задержка ответа | Среднее число ходов от адресации до ответа | 0-1: мгновенный ответ<br>>2: задержка |

#### D) **Визуализация** (`visualize.py`)
- **NetworkX** для построения графа коммуникаций
- **Matplotlib** для рендеринга
- **Узлы**: размер ~ активность, цвет = роль агента, обводка = последняя эмоция
- **Рёбра**: каждое сообщение = отдельная стрелка, цвет = тональность (красный→зелёный)

#### E) **Валидация** (`validators.py`) 🆕
- 8 валидаторов (грамматика, логика, мораль)
- Блокирует критические ошибки (токсичность, self-targeting, неанглийский язык)
- Подробнее — в разделе 3

#### F) **Веб-интерфейс** (`web_app.py`)
- **Flask API** для пошагового запуска симуляции
- Endpoints: `/api/start`, `/api/step`, `/api/state`
- UI: транскрипт диалога + граф + метрики + гипотезы

### Принципы реализации

1. **Строгая структура данных**
   - Pydantic-модель `AgentTurn` для валидации ответов LLM
   - Обязательные поля: `reply`, `tone`, `emotion`, `target`

2. **Принудительная адресация**
   - Каждое сообщение должно иметь **конкретного адресата**
   - Broadcasts (null/all) запрещены
   - Обеспечивает структурированность диалога

3. **Человекоподобность**
   - Короткие фразы (1-2 предложения)
   - Сокращения (I'm, don't, let's)
   - Инструкция `HUMAN_STYLE` в промптах

4. **Прозрачность и воспроизводимость**
   - Все логи в JSONL (машиночитаемый) + Markdown (человекочитаемый)
   - Графики сохраняются на каждом шаге
   - Timestamp в UTC для каждого хода

5. **Модульность и расширяемость**
   - Каждый компонент — отдельный модуль
   - Легко добавить новых агентов, валидаторы, метрики
   - Зависимости минимальны (OpenAI SDK, NetworkX, Flask)

## 2️⃣ Теоретические основы дипломной работы

### Используемые области знаний

#### A) **Большие языковые модели (LLM)**

- **Модель**: GPT-4o-mini (OpenAI)
- **Техника**: Function Calling (Structured Output)
  - Модель не просто генерирует текст, а **вызывает функцию** с JSON-аргументами
  - Гарантирует валидный формат ответа
  - Пример:
    ```json
    {
      "reply": "That's interesting! What's your take, Bob?",
      "tone": "positive",
      "emotion": "curious",
      "target": "Bob"
    }
    ```

**Литература:**
- Brown et al. (2020) — Language Models are Few-Shot Learners
- OpenAI Function Calling Documentation

#### B) **Multi-Agent Systems (MAS)**

- **Определение**: Система из нескольких автономных агентов, взаимодействующих для достижения общей цели
- **Применение**: Симуляция групповой дискуссии с разными ролями
- **Алгоритм взаимодействия**:
  - Round-robin scheduling с приоритетом адресата
  - Предотвращение ping-pong через анализ истории
  - Разнообразие адресатов (target diversity)

**Литература:**
- Wooldridge (2009) — An Introduction to MultiAgent Systems
- Ferber (1999) — Multi-Agent Systems

#### C) **Анализ диалога (Dialogue Analysis)**

**1. Sentiment Analysis (анализ тональности)**
- Классификация: positive / neutral / negative
- Используется для оценки "настроения" диалога
- Метрика: средняя тональность \(\in [-1, 1]\)

**2. Emotion Tracking**
- Детекция эмоций: joyful, angry, calm, skeptical, etc.
- Метрика: энтропия эмоций (Shannon entropy) для измерения разнообразия

**3. Addressee Prediction**
- Проверка правильности выбора адресата
- Метрика: % сообщений с явным адресатом

**Литература:**
- Liu (2012) — Sentiment Analysis and Opinion Mining
- Strapparava & Mihalcea (2008) — Learning to Identify Emotions in Text

#### D) **Теория графов (Graph Theory)**

- **Граф коммуникаций**: направленный граф \(G = (V, E)\)
  - \(V\) — агенты (узлы)
  - \(E\) — сообщения (рёбра): \((u, v)\) если \(u\) обращается к \(v\)
  
- **Метрики:**
  - **In-degree** / **Out-degree** — сколько раз агент был адресатом / говорил
  - **Reciprocity** — доля взаимных обменов: \(\frac{|\{(u,v): (u,v) \in E \land (v,u) \in E\}|}{|E|}\)

**Литература:**
- Newman (2010) — Networks: An Introduction
- Wasserman & Faust (1994) — Social Network Analysis

#### E) **Теория информации (Information Theory)**

- **Энтропия Шеннона** для эмоций:
  \[
  H = -\sum_{e \in \text{emotions}} p(e) \log_2 p(e)
  \]
  где \(p(e)\) — частота эмоции \(e\)

- **Интерпретация:**
  - \(H = 0\): одна эмоция (монотонность)
  - \(H > 1.5\): высокое разнообразие (возможная фрагментация)

**Литература:**
- Shannon (1948) — A Mathematical Theory of Communication
- Cover & Thomas (2006) — Elements of Information Theory

#### F) **Этика ИИ и моральные схемы** 🆕

- **Moral Schemas**: формальные правила для оценки этичности поведения агентов
- **Принципы** (из этики Beauchamp & Childress):
  - **Autonomy** (автономия) — запрет принуждения
  - **Non-maleficence** (ненанесение вреда) — запрет токсичности
  - **Justice** (справедливость) — предотвращение исключения участников
  - **Beneficence** (благодеяние) — поощрение сотрудничества

**Литература:**
- Beauchamp & Childress (2019) — Principles of Biomedical Ethics
- Wallach & Allen (2008) — Moral Machines: Teaching Robots Right from Wrong

#### G) **Human-Computer Interaction (HCI)**

- **Веб-интерфейс** для удобства взаимодействия
- **Визуализация** метрик и графов в реальном времени
- **Пошаговое управление** симуляцией (user control)

**Литература:**
- Shneiderman et al. (2016) — Designing the User Interface

## 3️⃣ Формализм в работе

### A) Формальная модель системы

Система определяется как кортеж:

\[
S = (A, H, M, V, \phi)
\]

где:
- \(A = \{a_1, a_2, ..., a_n\}\) — множество агентов
- \(H = [h_1, h_2, ..., h_t]\) — история диалога (последовательность ходов)
- \(M: A \times H \to \text{Turn}\) — модель генерации хода (LLM)
- \(V: \text{Turn} \times H \to \{\text{valid}, \text{invalid}\}\) — функция валидации
- \(\phi: H \to \text{Metrics}\) — функция аналитики

### B) Формализм хода (Turn)

Каждый ход \(h_i \in H\) — это структура:

\[
h_i = (\text{speaker}, \text{target}, \text{reply}, \text{tone}, \text{emotion}, t_i)
\]

где:
- \(\text{speaker} \in A\) — говорящий агент
- \(\text{target} \in A \setminus \{\text{speaker}\}\) — адресат (обязательно ≠ speaker)
- \(\text{reply} \in \Sigma^*\) — текст сообщения (строка)
- \(\text{tone} \in \{\text{positive}, \text{neutral}, \text{negative}\}\) — тональность
- \(\text{emotion} \in E\) — эмоция, где \(E = \{\text{joyful}, \text{calm}, \text{angry}, ...\}\)
- \(t_i \in \mathbb{N}\) — номер хода

**Ограничения:**
1. \(\text{target} \neq \text{speaker}\) (запрет self-addressing)
2. \(\text{reply} \neq \emptyset\) (сообщение не пустое)
3. \(\text{reply}\) содержит только латинские символы (English-only)

### C) Метрики (формулы)

#### 1. Средняя тональность

\[
\bar{\tau}(H) = \frac{1}{|H|} \sum_{h \in H} s(\text{tone}_h)
\]

где функция score:

\[
s(\text{tone}) = \begin{cases}
+1 & \text{if tone = positive} \\
0 & \text{if tone = neutral} \\
-1 & \text{if tone = negative}
\end{cases}
\]

#### 2. Энтропия эмоций

\[
H_{\text{emotion}} = -\sum_{e \in E} p(e) \log_2 p(e)
\]

где:
\[
p(e) = \frac{|\{h \in H : \text{emotion}_h = e\}|}{|H|}
\]

#### 3. Взаимность (Reciprocity)

\[
R(H) = \frac{|\{(u, v) \in P : (v, u) \in P\}|}{|P|}
\]

где \(P\) — множество пар (speaker, target) в истории:

\[
P = \{(\text{speaker}_h, \text{target}_h) : h \in H\}
\]

#### 4. Задержка ответа (Response Delay)

\[
D(H) = \frac{1}{K} \sum_{k=1}^{K} (t_{\text{reply}}^{(k)} - t_{\text{addressed}}^{(k)})
\]

где \(K\) — число пар "адресация → ответ", а \(t_{\text{reply}}^{(k)}\) и \(t_{\text{addressed}}^{(k)}\) — номера ходов.

### D) Граф коммуникаций

Граф \(G = (V, E)\):
- \(V = A\) (узлы = агенты)
- \(E = \{(u, v) : \exists h \in H_{\text{window}} : \text{speaker}_h = u \land \text{target}_h = v\}\)

где \(H_{\text{window}}\) — последние \(W\) ходов (окно).

**Вес ребра:**

\[
w(u, v) = |\{h \in H_{\text{window}} : \text{speaker}_h = u \land \text{target}_h = v\}|
\]

**Цвет ребра:**

\[
c(u, v) = \text{tone\_to\_color}\left(\frac{1}{w(u,v)} \sum_{\substack{h \in H_{\text{window}} \\ \text{speaker}_h = u, \text{target}_h = v}} s(\text{tone}_h)\right)
\]

где `tone_to_color` — линейная интерполяция между красным (−1) и зелёным (+1).

### E) Система валидации (моральные схемы)

**Моральная схема** \(M\) определяется как кортеж:

\[
M = (P, R, V)
\]

где:
- \(P = \{p_1, p_2, ..., p_m\}\) — множество **моральных принципов**
  - \(p_1\): Справедливость (fairness)
  - \(p_2\): Уважение автономии (autonomy)
  - \(p_3\): Инклюзивность (inclusivity)
  - \(p_4\): Ненанесение вреда (non-maleficence)

- \(R = \{r_1, r_2, ..., r_k\}\) — множество **правил** (паттернов)
  
  Каждое правило \(r_i: \Sigma^* \to \{0, 1\}\) проверяет, нарушается ли принцип.
  
  **Примеры:**
  
  \[
  r_{\text{exclusion}}(\text{reply}) = \begin{cases}
  1 & \text{if reply matches } \texttt{/(exclude|ignore)/} \\
  0 & \text{otherwise}
  \end{cases}
  \]
  
  \[
  r_{\text{coercion}}(\text{reply}) = \begin{cases}
  1 & \text{if reply matches } \texttt{/(force|must do)/} \\
  0 & \text{otherwise}
  \end{cases}
  \]

- \(V: \{r_1, ..., r_k\} \to L\) — функция **оценки серьезности** нарушения
  
  где \(L = \{\text{info}, \text{warning}, \text{error}, \text{critical}\}\)

**Функция валидации хода:**

\[
\text{validate}(h) = \begin{cases}
\text{valid} & \text{if } \forall r \in R: r(\text{reply}_h) = 0 \lor V(r) \neq \text{critical} \\
\text{invalid} & \text{otherwise}
\end{cases}
\]

**Таблица правил:**

| Правило | Паттерн (regex) | Принцип | Уровень |
|---------|-----------------|---------|---------|
| \(r_1\) | `/(exclude\|ignore\|leave out)/` | Inclusivity | ERROR |
| \(r_2\) | `/(force\|must do\|make you)/` | Autonomy | ERROR |
| \(r_3\) | `/(stupid\|idiot\|moron)/` | Non-maleficence | CRITICAL |
| \(r_4\) | `/(you always fail\|you never)/` | Respect | ERROR |

### F) Алгоритм выбора следующего говорящего

```
function next_speaker(history, agents):
    if history is empty:
        return agents[0]
    
    last = history[-1]
    last_target = last.target
    last_speaker = last.speaker
    
    # Приоритет: адресат из последнего хода
    idx = find_index(agents, last_target)
    
    # Проверка ping-pong
    if len(history) >= 2:
        prev = history[-2]
        if prev.target == last_speaker AND prev.speaker == last_target:
            # Выбрать третьего агента
            idx = find_index(agents, agent NOT IN {last_speaker, last_target})
    
    if idx is None:
        # Fallback: round-robin
        idx = (current_turn % len(agents))
    
    return agents[idx]
```

**Формально:**

\[
\text{next\_speaker}(H, A) = \begin{cases}
a_{\text{target}_{h_{|H|}}} & \text{if no ping-pong} \\
a_k \in A \setminus \{a_{\text{speaker}_{h_{|H|}}}, a_{\text{target}_{h_{|H|}}}\} & \text{if ping-pong detected} \\
a_{(|H| \mod |A|)} & \text{fallback}
\end{cases}
\]

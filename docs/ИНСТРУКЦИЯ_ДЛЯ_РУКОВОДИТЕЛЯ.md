## 1. Что это за проект

Многоагентный симулятор диалогов, в котором несколько LLM-агентов (в т. ч. с
заданными чертами личности Big Five) общаются между собой в выбранном
контексте. На каждом 5-м ходе автоматически считаются:

- сетевые метрики взаимодействий (плотность, центральность, кластеризация);
- эмоциональный климат и распределение диалоговых актов;
- стадия группового развития по модели Tuckman / Wheelan;
- 5–13 содержательных гипотез с привязкой к научной литературе (Bunt 2020,
  Cowen & Keltner 2017, Gonzales et al. 2010, Shuffler et al. 2018, …).

Параллельно работает **observer-агент** — независимый LLM-наблюдатель, который
формирует своё качественное мнение и сравнивает его с алгоритмическими выводами
(методологическая триангуляция, Denzin 2012).

Назначение — пилотный инструмент для исследований групповой коммуникации:
гипотезы из теории → симуляции → метрики → отчёт.

## 2. Что нужно установить

1. **Python 3.10 или новее** (проверено на 3.14).
2. **Git** (для клонирования; опционально, если папка уже передана архивом).
3. **API-ключ** одного из провайдеров:
   - **OpenAI** (ChatGPT) — `https://platform.openai.com/api-keys`
   - **DeepSeek** — `https://platform.deepseek.com/api_keys` (дешевле,
     полностью совместим с OpenAI SDK).

После клонирования проекта:

```bash
cd /путь/к/Mephi/agent_dialogue_sim
python3 -m venv .venv          # создать виртуальное окружение
source .venv/bin/activate      # активировать (macOS/Linux)
# Windows:  .venv\Scripts\activate
pip install -r requirements.txt
```

Список зависимостей — `requirements.txt`: openai, pydantic, python-dotenv,
networkx, matplotlib, Flask, openpyxl, numpy, scipy, statsmodels, pandas.

**`.env` файл создавать необязательно** — API-ключ можно ввести прямо в
интерфейсе. Если хочется зашить ключ на машине, создайте
`agent_dialogue_sim/.env`:

```env
OPENAI_API_KEY=sk-...
# OPENAI_BASE_URL=https://api.deepseek.com/v1   # только для DeepSeek
# OPENAI_MODEL=deepseek-chat                    # или gpt-4o-mini
```

## 3. Запуск веб-приложения за 5 минут

Из корня репозитория `Mephi/` (на уровень выше папки `agent_dialogue_sim`):

```bash
python3 -m agent_dialogue_sim.webapp.app
```

В терминале появится:

```
 * Serving Flask app 'app'
 * Running on http://0.0.0.0:8080
```

Открыть в браузере: **http://localhost:8080**.

> Если выдаёт `Address already in use` — значит старый сервер ещё висит. Убить:
> `lsof -ti:8080 | xargs kill` (macOS/Linux) и запустить снова.

Останавливается сервер по **Ctrl+C** в терминале.

## 5. Веб-интерфейс по шагам

### Шаг 0 — выбор провайдера и ввод токена

После открытия `http://localhost:8080` первым делом появится экран
**«Подключение к модели»**:

- Карточка **ChatGPT** — OpenAI, модель `gpt-4o-mini`.
- Карточка **DeepSeek** — `deepseek-chat`, дешевле в ~10 раз, ответы похожего
  качества для большинства задач.
- Поле **API-токен** (тип `password`, не сохраняется ни на диск, ни в
  localStorage; уходит только в backend этой сессии).

Ссылки на страницы выдачи токенов даны прямо в карточках.

### Шаг 1 — число агентов и контекст

- Ползунок: **2…20 агентов**.
- Селектор контекста (research seminar / university coursework / startup MVP).
- Чекбокс **«Войти в диалог как участник»** — если включён, в диалоге появится
  «User», к которому смогут обращаться агенты.
- Кнопка «← Сменить провайдера» возвращает к Шагу 0.

### Шаг 2 — настройка каждого агента

Для каждого агента доступна детальная анкета:

- имя, роль, цвет (для отрисовки в графе);
- блок «Базовая информация» (бэкграунд, мотивация);
- блок «Паттерны социального поведения» (8 вопросов: стиль общения, реакция
  на разногласия, доверие, лидерство, реакция на критику…);
- блок «Стиль речи» (речевые привычки, любимые темы, реакция на стресс,
  «фирменная фраза»).

Любое поле можно оставить пустым — будет использован дефолт для выбранной роли.

### Главный экран

После «Начать диалог» открывается основной интерфейс с вкладками:

- **💬 Диалог** — лента реплик, граф взаимодействий, карточки verdict'ов,
  эвристические гипотезы и блок метрик.
- **🔬 Научный анализ** — полный markdown-отчёт + карточки научных гипотез
  с раскрывающимся **«Краткий отчёт»** по каждой (см. § 6).
- Сверху: кнопка **«Следующий ход»**, выбор языка реплик (RU/EN), кнопки
  скачивания JSONL и Markdown-логов.
- Ссылка справа вверху — переход к каузальным экспериментам (см. § 8).

### Ход диалога

Каждое нажатие «Следующий ход» делает один шаг — система выбирает
очередного говорящего (приоритет тому, кто давно молчал; антимонополизация),
генерирует реплику через LLM, прогоняет её через 8 валидаторов и добавляет в
ленту.

Каждые **5 ходов** автоматически:

1. перерисовывается граф (4 панели: сеть, центральности, sociomatrix, timeline);
2. пересчитываются метрики;
3. генерируются научные гипотезы и научный отчёт;
4. сохраняется validation report;
5. запускается observer-агент (если ходов ≥ 3).

## 6. Какие отчёты появляются и что они означают

### 6.1 Граф взаимодействий

Файл `analytics/visualize.py` (функция `draw_interactions_pro`). Это
4-панельный публикационного качества дашборд:

| Панель | Что показывает |
|---|---|
| **Сеть** (force-directed) | Узлы = агенты (цвет = личный, обводка = последняя эмоция); рёбра = адресации; halo = betweenness centrality (Burt 2005) |
| **Центральности** | In/Out/Betweenness по агентам (Freeman 1979) |
| **Sociomatrix** | Тепловая карта «отправитель → получатель», цвет = средний тон |
| **Timeline ходов** | По каждой реплике маркер с цветом по тону |
| **Sparkline тренда тона** | Скользящее среднее по 3 ходам |

Отдельно в нижней части картинки — научные ссылки (Borgatti 2009, Moreno 1934,
Sacks/Schegloff/Jefferson 1974, Newman 2010).

### 6.2 Базовые метрики (`analytics/basic.py`)

Внизу вкладки «Диалог» — карточки:

- доля положительного / нейтрального / отрицательного тона;
- reciprocity (взаимность обращений);
- targeting fairness (равномерность адресации);
- emotion entropy.

Полная Markdown-таблица — в папке логов под именем `metrics_turn_*.md`.

### 6.3 Научный анализ (`analytics/scientific.py`)

Полный markdown-отчёт, который показывается на вкладке «🔬 Научный анализ» и
сохраняется в `scientific_turn_*.md`. Содержит:

- Team Temporal Dynamics — текущая фаза команды и confidence (Shuffler 2018, Mathieu 2017);
- Emotional Climate — распределение 8 базовых эмоций (Cowen & Keltner 2017);
- Dialogue Acts — task ratio, socio-emotional ratio, pos/neg ratio (ISO 24617-2, Bunt 2020);
- Multidimensional Networks — плотность, кластеризация, центральности (Contractor 2012);
- Network Dynamics — социометрический статус и cohesion (Reagans 2016);
- Turn-Taking — Gini-неравенство реплик, adjacency completion (Gonzales 2010, Tausczik 2010);
- Список научных гипотез с обоснованием и рекомендациями.

### 6.4 Краткие отчёты по гипотезам

Под каждой карточкой гипотезы есть кнопка **«▸ Краткий отчёт»**. По клику
раскрывается панель с тремя секциями:

- **Метод** — как именно измерялось (1 предложение);
- **Метрики** — таблица конкретных значений с порогами;
- **Интерпретация** — почему сработал триггер и что это значит, со ссылкой на
  теорию (Burt, Losada, Fredrickson, Searle, Sacks/Schegloff и др.).

Это позволяет за 10 секунд понять, на чём основан конкретный вывод, не лезя в
исходный код.

### 6.5 Validation Report (`analytics/hypothesis_validator.py`)

Файл `validation_turn_*.md`. По каждой гипотезе фиксируется:

- статус (`confirmed` / `partial` / `refuted` / `pending`);
- сырые метрики на текущем окне;
- дельта относительно предыдущего окна;
- ссылка на доказательство (какой именно агент / какие именно реплики);
- evidence-trail — список номеров ходов, поддерживающих гипотезу.

Можно скачать по кнопке «📥 Download Validation Report».

### 6.6 Observer Agent (`core/observer_agent.py`)

Независимый LLM-наблюдатель — он **не участвует** в диалоге, а получает
полный лог и формирует:

- качественный отчёт «что я вижу в этой группе»;
- свою оценку каждой гипотезы (confirmed / partial / not_confirmed / insufficient);
- triangulation summary — сходятся ли его выводы с алгоритмическими.

Файл `observer_turn_*.md`. Это основной механизм **convergent validity** —
если человек, алгоритм и observer сходятся на одном выводе, доверие к
заключению повышается.

## 7. Где система хранит логи и графы

Все артефакты по умолчанию складываются **вне репозитория**, в системный
tmp-каталог, чтобы не засорять git:

- **macOS / Linux:** `/tmp/agent_dialogue_sim/` (точный путь — `tempfile.gettempdir()/agent_dialogue_sim`)
- **Windows:** `%TEMP%\agent_dialogue_sim\`

Структура:

```
$AGENT_RUNTIME_DIR/
├── logs/
│   ├── dialog.jsonl                ← машино-читаемый лог (строка = ход)
│   └── dialog.md                   ← человеко-читаемая транскрипция
└── outputs/
    ├── graph_turn_0005.png         ← 4-панельный граф (ход 5, 10, 15…)
    ├── metrics_turn_0005.md        ← базовые метрики
    ├── scientific_turn_0005.md     ← научный анализ
    ├── validation_turn_0005.md     ← проверка гипотез
    └── observer_turn_0005.md       ← отчёт наблюдателя
```

Поменять расположение можно через переменные окружения в `.env`:

```env
AGENT_RUNTIME_DIR=/Users/имя/мои_прогоны
AGENT_LOG_DIR=/Users/имя/мои_прогоны/logs
AGENT_OUTPUT_DIR=/Users/имя/мои_прогоны/outputs
```

Прямо из веб-интерфейса доступны:

- кнопка **«Скачать JSONL»** (`/download/log`) — сырые ходы;
- кнопка **«Скачать MD»** (`/download/log_md`) — транскрипция;
- кнопка **«📥 Скачать отчёт»** на панели verdict'ов — markdown с verdict'ами;
- кнопка **«📥 Download Validation Report»** на вкладке Scientific Analysis.

## 8. CLI и каузальные эксперименты

### 8.1 CLI-режим (`main.py`)

Тот же симулятор, но в терминале, без веб-интерфейса. Удобно для batch-прогонов:

```bash
python3 -m agent_dialogue_sim.main
```

Артефакты складываются туда же, что и из веба.

### 8.2 Каузальные интервенции (`experiments/run_causal.py`)

Это реализация **do-оператора Перла**: запускаются **пары** диалогов, в которых
один агент имеет высокое значение черты (treatment), второй — низкое (control),
все остальные условия одинаковы. Так измеряется *причинный* эффект черты на
исход.

Пример: проверить, влияет ли низкая agreeableness агента «Critic» на
эмоциональный климат группы:

```bash
python3 -m agent_dialogue_sim.experiments.run_causal \
    --target-agent Critic \
    --trait agreeableness \
    --treatment-value 0.9 \
    --control-value 0.1 \
    --n-pairs 8 \
    --n-turns 10
```

В `experiments/results/<id>__<timestamp>/` появятся:

- `pairs.jsonl` — сырые пары прогонов;
- `summary.json` — агрегированные эффекты (Cohen d, p-value);
- `REPORT.md` — человеко-читаемый отчёт.

### 8.3 Серии экспериментов и A/B-сравнения

- `experiments/run_experiments.py` — запуск пакета экспериментов по
  конфиг-файлу из `experiments/configs/`. Удобно, когда нужно прогнать
  одинаковый сценарий с разными значениями черт.
- `experiments/ab_experiments.py` — попарные сравнения условий A vs B с
  одинаковыми сидами; используется для оценки эффектов отдельных факторов.
- `experiments/runner.py` — общий низкоуровневый runner, на который опираются
  все скрипты выше.

На веб-странице есть отдельная вкладка «🔬 Каузальные эксперименты» —
ссылка справа вверху главного экрана.

## 9. Научная методология и валидация

### 9.1 Зачем гипотезам можно доверять

Каждая метрика и каждый порог взяты из рецензируемой литературы 2010–2025.
Например:

- порог Gini > 0.3 для неравенства реплик — Gonzales/Hancock/Pennebaker (2010);
- task_ratio > 0.7 — Bunt et al. (2020), ISO 24617-2;
- фазы команды — Shuffler et al. (2018), Mathieu et al. (2017);
- 8 базовых эмоций — Cowen & Keltner (2017);
- директивы > 0.4 — Jurafsky & Martin (2024).

Все ссылки видны прямо в карточках гипотез (поле `reference`) и в кратком
отчёте (поле `interpretation`).

### 9.2 Слои валидации

| Слой | Что обеспечивает |
|---|---|
| Construct validity | привязка метрик к рецензируемым теориям |
| Test-retest reliability | детерминированность — один лог → один результат |
| Convergent validity | сходимость алгоритма и observer-агента |
| Inter-rater reliability | 5 прогонов проверены психологом, ≈80% совпадения |
| Validation report | per-hypothesis evidence-trail с дельтами |
| Multi-level validators | фильтр мусорных реплик до анализа |

### 9.3 Что можно улучшить для публикации

- посчитать **Cohen's κ** или **Krippendorff's α** формально (с использованием
  `nltk.metrics.agreement`), а не «на глаз»;
- провести **слепую** разметку эксперта (без подсказок алгоритма);
- добавить **≥3 рейтера**, чтобы κ был статистически устойчивым;
- зафиксировать **код-бук** (правила разметки) до прогонок.

Подробнее — в `docs/preregistration.md`.

## 10. Автоматические тесты

Запуск всех тестов из корня репозитория:

```bash
pip install pytest
pytest agent_dialogue_sim/tests/ -v
```

Что покрыто (выборка):

- `test_validators.py` — каждый из 8 валидаторов реплик;
- `test_statistical_tests.py` — t-test, Mann-Whitney, Cohen d, p-values;
- `test_wheelan_classifier.py` — корректность определения фазы команды;
- `test_manipulation_check.py` — что вмешательство в Big Five действительно
  даёт ожидаемый сдвиг outcome;

## 11. FAQ и устранение неполадок

**«Address already in use» при запуске.**
Старый сервер ещё висит. `lsof -ti:8080 | xargs kill`, затем перезапустить.

**Не запускается 5-й ход / «Ошибка хода».**
На 5-м ходе впервые запускается тяжёлый блок (граф + scientific + observer +
advanced analytics — это **дополнительные LLM-вызовы**). Возможные причины:

- кончились API-кредиты — проверить баланс в личном кабинете провайдера;
- провайдер отвечает медленнее, чем frontend ждёт — увеличить таймаут или
  использовать `gpt-4o-mini` вместо более тяжёлой модели;
- ошибка в логе сервера (терминал, где запущен Flask) — там будет Traceback.

**Где смотреть лог сервера?**
В терминале, где запущена команда `python3 -m agent_dialogue_sim.webapp.app` —
все исключения и `[Warning]` пишутся туда.

**Можно ли менять модель?**
Да — либо через `OPENAI_MODEL=...` в `.env`, либо передав поле `model` в
`/api/start`. Backend по умолчанию выбирает модель по провайдеру:
`gpt-4o-mini` для ChatGPT, `deepseek-chat` для DeepSeek.

**Графы выглядят квадратными и не на весь экран.**
Браузер показывает кешированную старую картинку. Hard reload — **Ctrl+Shift+R**
(или «Новая сессия»: старые графы автоматически чистятся).

**Где посмотреть архитектуру?**
Папка `uml_diagrams/` — там `agent_dialogue_sim.puml` (полная class diagram),
`agent_dialogue_sim_compact.puml` (компактная), `agent_dialogue_sim_simple.puml`
(упрощённая), `agent_dialogue_sim_final.puml`, `agent_dialogue_sim_presentation.puml`
(для презентации), `use_case_diagram.puml` (use cases), `architecture_diagram.puml`.
Открываются любым PlantUML-вьюером или на `https://www.plantuml.com/plantuml`.

**Как остановить эксперимент?**
В веб-режиме — Ctrl+C в терминале с сервером. CLI-эксперименты (`run_causal`)
тоже останавливаются по Ctrl+C, частично сохранённые результаты остаются в
`experiments/results/`.
